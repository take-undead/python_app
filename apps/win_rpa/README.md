# win_rpa

Windows アプリを自動操作して CSV を出力させ、複数の CSV を結合してまとめる。
月 1 回のルーティンワークを、スケジュール実行で無人化することを目標にする。

作った経緯・設計判断の理由・現在地は [DEVLOG.md](DEVLOG.md) に分けてある。
**作業を再開するときはそちらから読むこと。**

## 実行

```powershell
python apps/win_rpa/main.py                        # 画面を開く
python apps/win_rpa/main.py --run 売上集計           # 無人実行（スケジューラ用）
python apps/win_rpa/main.py --run 売上集計 --dry-run  # 操作せず確認だけ

python apps/win_rpa/pick.py                        # 要素ピッカー単体（下調べ用）
python tools/mock_target.py                        # 練習用ダミーアプリ
```

### エクスプローラーから起動する

`.py` をそのままダブルクリックすると、`.venv` ではなくシステム側の
Python が使われて `pywinauto` が無く失敗する。ショートカットを作る。

```powershell
python tools/make_shortcut.py win_rpa --name "Win RPA" --desktop
```

`apps/win_rpa/Win RPA.lnk`（と、デスクトップ）ができる。中身は
`.venv\Scripts\pythonw.exe` に `main.py` を渡す形で、コンソールは出ない。

起動しないときは `--console` を付けて作り直すと例外が読める。
なお `pythonw.exe` でも起動時の例外は `logs/起動エラー.log` に残り、
ダイアログにも出る（黙って何も起きない状態を避けるため）。

`.lnk` にはこの PC の絶対パスが入るので Git 管理外にしてある。
別の PC では作り直すこと。

## 使い方

1. 対象アプリを起動しておく
2. ［新規］でシナリオを作る
3. 手順一覧の右上［＋ 手順を追加］で操作を選ぶ
4. ［要素を選ぶ...］を押し、対象アプリのボタンにマウスを乗せて **F8**
5. 手順を 1 つ足すたびに［ここまで試し実行］で確かめる
6. 手順が増えたら［グループ］で束ねる
7. ［保存］→［スケジュール...］で毎月の実行日時を登録する

### まだベータ版であることを画面に出す

ツールバーの右端に **⚠ ベータ版 0.9.0** と出る。押すと「について」の
小窓が開き、何をするソフトかと、何に気をつけるべきかが読める。

実機（対象の業務アプリ）での確認が済んでいない状態を、画面を見ただけで
分かるようにしてある。**確認が済んだら `logic/appinfo.py` の
`IS_BETA` を False にする。** 色と警告が消え、表示が
「バージョン 0.9.0」に変わる。

版と説明の文言は `logic/appinfo.py` の 1 か所に置いてある。

### 操作は分類から選ぶ

［＋ 手順を追加］は分類ごとの入れ子になっている。

| 分類 | 入っているもの |
| --- | --- |
| アプリを操作する | 起動 / ボタンを押す / 文字を入力 / チェック / 一覧から選ぶ / 閉じる |
| ファイルとフォルダ | 保存ダイアログ / フォルダを作る / 保存先を選ぶ / コピー／移動 |
| 確認する | 画面の表示 / ファイルができたか |
| その他 | CSV をまとめる / 用意した処理を実行する |

分類は `logic/actions.py` の各 `ActionSpec` に `category=` で書いてある。
操作を増やしても `ui/` は触らない。

**選べない操作がある。**「CSV をまとめる」は前に「フォルダを作る」が
無いと選べず、理由がその場に出る。

```
その他 ▸  CSV をまとめる（先に「フォルダを作る」の手順が必要です）   ← 灰色で押せない
          用意した処理を実行する
```

### 手順をグループで束ねる

手順一覧はツリーになっていて、手順を**グループ**にまとめられる。

一覧で手順を選び（Ctrl / Shift で複数選べる）、［グループ］→
［選んだ手順をまとめる...］で名前を付ける。見出しをクリックすると
折りたためる。

| したいこと | やり方 |
| --- | --- |
| まとめる | 手順を選んで［グループ］→［選んだ手順をまとめる...］ |
| 別のグループへ移す | 手順を選んで［グループ］→［別のグループへ移す...］ |
| グループから出す | 手順を選んで［グループ］→［グループから出す］ |
| 名前を変える | 見出しを選んで［グループ］→［グループ名を変更...］ |
| グループごと動かす | 見出しを選んで ↑ ↓ |
| 手順を隣のグループへ | 手順を選んで、境目で ↑ ↓ をもう一度押す |

**グループは見出しでしかない。** 実行順は今まで通り上から 1 本の直線で、
分岐も繰り返しもない。長いシナリオを読めるようにするためだけのもの。

### ファイル操作

| 操作 | 何をするか |
| --- | --- |
| フォルダを作る | 出力先フォルダを作る。名前は年月日などの型から自動で決まる |
| 保存先フォルダを選ぶ | これ以降の手順の基準フォルダを切り替える |
| ファイルをコピー／移動する | 出来上がった CSV を別フォルダへ運ぶ |

**フォルダ名は打たずに選ぶ。** ［型 ▼］に年月日の並べ方が入っている。

| 選ぶもの | 出来上がる名前 |
| --- | --- |
| 年月 | `202608` |
| 年月（区切りあり） | `2026-08` |
| 年月日 | `20260828` |
| 年 の下に 月 | `2026\08`（フォルダが 2 段になる） |
| 前月 | `202607` |
| シナリオ名＋年月 | `売上集計_202608` |

選ぶと、その下に**実際に出来上がるフルパス**が出る。既にあるかどうかも
そこに出るので、毎月同じフォルダに上書きしていないか確認できる。
先頭に文字を足したい場合は欄に直接書き足せる（`月次_{yyyymm}` など）。

「フォルダを作る」「保存先フォルダを選ぶ」を通すと、**それ以降の手順の
保存先が切り替わる**。ファイル名だけを書いた項目（`売上_{yyyymm}.csv` など）は
その時点の保存先を基準に解決される。

コピーの対象も打たずに選ぶ。［型 ▼］に「すべてのファイル」「CSV すべて」
「今月分の CSV」などが入っていて、選ぶと**今そこに何件あるか**が下に出る。
0 件のまま気づかず組んでしまうのを防ぐため。

`最低件数` を下回ると失敗にする。0 件を黙って次の手順に渡さないための歯止め。

`同じ名前のとき` の既定は**飛ばす**。毎月動かすので、行き先に前月分が残って
いても止まらず、かつ黙って消さないようにしてある。上書きを選ぶと
行き先のファイルは消える。

### CSV をまとめる（特殊な手順）

想定している使い方は、**日単位で貯まった CSV を 1 か月ぶん、
1 本の連続データにする**こと。

```
日次/  ← 対象アプリが毎日 1 本ずつ吐く
    売上_20260801.csv
    売上_20260802.csv        1  フォルダを作る          → 日次/202608
    ...                      2  ファイルをコピーする    → 31 本を入れる
    売上_20260831.csv        3  CSV をまとめる          → 月次_202608.csv
```

**「フォルダを作る」で作ったフォルダの中の CSV を全部**読み込み、
日時の古い順に並べ替えて 1 つにまとめ、**同じフォルダに**置く。

指定するのは、できあがるファイルの名前だけ。

| 項目 | 内容 |
| --- | --- |
| できあがる名前 | ［型 ▼］から選ぶ（`まとめ_{yyyymmdd}.csv` など）。`.csv` は自動で付く |
| 元ファイル名の列を足す | どの CSV から来た行かを末尾の列に残す |
| 最低行数 | これを下回ると失敗にする |

対象は選ばせない。まとめる先が「フォルダを作る」で作った場所なので、
そこに入っているものが対象、という以外の解釈が無いため。

**並べ替えの列は自動で見つける。** 見出しの**先頭 4 列**の中から、
名前に「日時」「日付」「年月日」「date」などが入っている列を先に試し、
無ければ中身を読んで日時として通るかで判断する。使った列は実行ログに出る。

**時刻まで見て並べる。** 日単位のファイルを 1 か月ぶんまとめる用途では、
時刻を落とすと同じ日の中が元ファイルの並び順のまま残ってしまうため。

読める書き方は次のとおり。ファイルごとに違っていても混ぜて並べられる。

```
2026-08-28 10:30:00    2026/8/5 9:07     2026-08-28T10:30:00
2026-08-28 10:30:00.5  20260828 07:05:00  20260828070500
2026年8月28日 14時05分
2026-08-28   2026/8/5   20260828   2026年8月28日   2026.08.28   （日付だけも可）
2026-08      2026/08                                            （年月だけも可）
```

- 日時として読めなかった行は**捨てずに末尾**へ回す
- 先頭付近に日時の列が無ければ、読み込んだ順のままにして警告を出す
- できあがるファイル自身は対象から除く（2 回目に動かしても行が倍にならない）

実行ログに**まとまった期間**が出る。1 か月ぶんが揃っているかを、
ファイルを開かずに確かめられる。

```
[info]   「日時」の古い順に並べ替えました
[info]   2026-08-01 10:00:00 〜 2026-08-31 17:00:00 の 93 行
[ok]    31 件を 93 行にまとめました（...\202608\月次_202608.csv）
```

**前に「フォルダを作る」が無いと、この手順は追加できない。**
まとめる先が決まらないため。既にあるシナリオでこの条件が崩れた場合は
一覧に ⚠ が付き、実行時は対象アプリを起動する前に止まる。

### スケジュールの登録

［スケジュール...］を開き、実行する日と時刻を決めて［登録する］を押す。
Windows のタスクスケジューラに登録され、アプリを開いていなくても動く。

登録されるのは 2 つ。

| タスク名 | 内容 |
| --- | --- |
| `win_rpa_<シナリオ名>_実行` | 本番。CSV を出力して結合する |
| `win_rpa_<シナリオ名>_確認` | 確認実行。操作せず、要素が見つかるかだけ調べる |

確認のほうを本番より前の日時にしておくと、対象アプリの更新で壊れていた
場合に事前に気づける。月 1 回しか動かないので、当日に初めて知るのは遅い。

画面下部に**全シナリオの登録一覧**が出る（シナリオ／種類／実行日時／次回）。
行を選んで［選んだものを削除］で個別に消せる。開いているシナリオ以外の
ものも消せるので、取り残されたタスクをここで片付けられる。

登録済みの日時は開いたときに入力欄へ読み込まれる。既定値に戻ると
「今どう登録されているか」が分からないまま上書きしてしまうため。

**シナリオを削除・改名すると、スケジュールも自動で追従する。**
削除なら解除、改名なら同じ日時で新しい名前に付け替える。これを怠ると、
実体の無いシナリオを毎月起動しては失敗し続けるタスクが残る。

**画面がロックされていると動かない。** UI を操作するため、実行時刻に PC が
ログオン状態である必要がある。ここは自動化しきれない。

手順を全部組んでから通しで試すと、どこが悪いか分からなくなる。
**1 手順ごとに［ここまで試し実行］**で確かめながら進めること。

実行日の前日に確認実行を仕込めるようにしてある。
月 1 回しか動かさないので、当日に初めて壊れているのを知るのを避けるため。

## 構成

```
main.py                エントリポイント（--run で無人実行）
pick.py                要素ピッカーの CLI（対象 PC に持ち込んで下調べに使う）

logic/picker.py        カーソル位置の UI 要素を採取する
logic/shortcuts.py     デスクトップ／スタートメニューのショートカット一覧
logic/actions.py       手順のスキーマ・差し込み変数・Step / Scenario
logic/runner.py        実行エンジン
logic/merger.py        CSV 結合
logic/winfind.py       HWND からウィンドウを探す（共通ダイアログ対策）
logic/storage.py       シナリオの保存・読み込み
logic/schedule.py      タスクスケジューラへの登録
logic/folder_dialog.py フォルダ選択（askdirectory が使えないため自前）
logic/appinfo.py       アプリ名・版・「について」に出す説明

ui/main_window.py      メイン画面（手順のツリー・実行ログ）
ui/step_form.py        選択中の手順の編集フォーム（スキーマから組み立てる）
ui/field_editors.py    入力項目のウィジェット（kind → ウィジェット）
ui/picker_dialog.py    要素を採取する小窓
ui/app_chooser.py      起動するアプリを選ぶ小窓
ui/group_chooser.py    手順を移す先のグループを選ぶ小窓
ui/about_dialog.py     用途と注意点を出す小窓（版表示をクリックで開く）
ui/schedule_dialog.py  スケジュール登録の小窓

scenarios/             シナリオ（JSON）
work/                  対象アプリが出力した CSV と結合結果（Git 管理外）
logs/                  実行ログと失敗時の画面（Git 管理外）
```

アクションを 1 つ増やすときは、`logic/actions.py` の `ACTIONS` に
宣言を足し（`category=` で［＋ 手順を追加］のどこに入るかを、
`requires=` で先に必要な手順を決める）、`logic/runner.py` に
`_do_<名前>` を書くだけでよい。**`ui/` は触らない。**

## 設計方針

### 記録するのは座標ではなく「要素の同一性」

マクロレコーダー的にマウス座標を記録すると、ウィンドウ位置が変わった時点で壊れる。
クリック対象の **AutomationId / 名前 / 種類 / 構造上の位置**を採取して残し、
実行時はそれで要素を探す。

照合は次の順に試し、前段が外れたら次に落ちる。

1. `auto_id`（最も安定）
2. `name` + `control_type`
3. `index_path`（同じ種類の中で何番目か）

複数持たせるのは、アプリが更新されて片方が変わっても動き続けるようにするため。
`class_name` は記録するが**照合には使わない** — WinForms のクラス名は
`WindowsForms10.BUTTON.app.0.22c71e1_r8_ad1` のように実行ごとに変わる
ハッシュを含むため。

### ウィンドウの題名は完全一致

「終わった合図」の「ウィンドウが出る」は、最上位ウィンドウを列挙して
題名を**完全一致**で照合する。部分一致も前方一致もしない。

そのため題名が実行のたびに変わるウィンドウには使えない
（`売上管理システム - 2026年08月`、`売上.csv - メモ帳` など）。
その場合は「要素が現れる」「要素が押せるようになる」
「表示に文字が現れる」を使う。

打ち間違いで永久に見つからない手順ができるのを防ぐため、
題名は今開いているウィンドウの一覧から選ぶ形にしてある。
一覧には UWP の隠しウィンドウが混ざるので、`DWMWA_CLOAKED` で除いている
（`IsWindowVisible` では除けない）。

### 待ちは手順の一部として記録する

各ステップに「次に何が現れたら成功か」（`wait_for`）を持たせる。
`sleep` で書くと、実行環境や当日の負荷で必ずいつか足りなくなる。

### 前提のある手順は、置く前に止める

「CSV をまとめる」は前の手順が作ったフォルダを使う。置けてしまうと、
実行して初めて成り立たないことに気づく。月 1 回しか動かさないので、
それは遅すぎる。

前提は `ActionSpec.requires` として**宣言側**に書き、次の 3 か所で効かせている。

1. ［＋ 手順を追加］— 満たしていない操作は灰色にし、理由をラベルに出す
2. 一覧と保存前の検証 — `Scenario.step_problems()` が ⚠ を付ける
3. 実行の開始時 — **対象アプリを起動する前に**止める

3 が要るのは、8 手順進んでから「先にフォルダを作る手順が要る」と言われても
遅いため。1 だけだと、種類のドロップダウンで後から切り替えた場合に漏れる。

### 検証ステップを手順に含める

「CSV が出来て、想定の行数がある」ところまでが手順。ここが無いと、
空ファイルを黙って結合して終わる。

### 分岐とループは入れない

`if` / `while` / 変数を入れると、手順一覧が入れ子のツリーになり、
条件式を書く UI とデバッグ機能が要る。月次ルーティンは平坦な直線で書ける。
特殊処理が必要になったら `run_python` アクション（用意したスクリプトを呼ぶ）で吸収する。

### グループは見出しだけ

手順が 20 を超えると一覧が読めなくなるので、ツリーで束ねられるようにした。
ただし**入れ物は作っていない**。`Step.group` という名札を 1 つ足しただけで、
`Scenario.steps` は今まで通り 1 本のリスト。同じ名札が隣り合っている区間を
`Scenario.groups()` が塊として返し、画面がそれを親ノードとして描く。

こうすると実行エンジンも `upto`（ここまで試し実行）も保存形式も変わらない。
入れ子の入れ物を持つと、ここに「入れ子の何番目まで実行」という概念が
生まれ、分岐を入れないと決めた意味が薄れる。

同じ名札が離れて置かれると見出しが 2 つに割れるため、グループ操作の直後だけ
`normalize_groups()` で先に出たほうへ寄せる。↑↓ の入れ替えでは呼ばない
（並べ替えた結果が勝手に動くと、何が起きたか分からなくなるため）。

### 保存先は実行中に動く

「フォルダを作る」「保存先フォルダを選ぶ」は `Runner` の作業フォルダを
差し替える。相対指定のファイルはその時点の作業フォルダを基準に解決するので、
差し込み変数の `{work_dir}` も同時に更新する（片方だけ変えると食い違う）。

確認実行では**フォルダは作らないが、保存先の切り替えは行う**。
切り替えないと、確認実行のときだけ以降のパスが本番と違うものになり、
確認の意味が無くなるため。

### ファイルを消す操作は入れない

削除アクションは用意しない。月 1 回・無人で動くものが誤って消すと、
気づくのが 1 か月後になる。片付けは人の手でやる。

コピーの「同じ名前のとき」の既定も**飛ばす**にしてある。上書きは
選んだときだけ。

### シナリオは何本でも持てる

`scenarios/` に 1 シナリオ 1 ファイルで貯まり、上部のドロップダウンで
切り替える。月次・週次・別システム向けを並べて持てる。

取り違えを防ぐため、次の場面で必ず確認を出す。月 1 回しか触らないので、
黙って消えると気づくのが 1 か月後になるため。

- 未保存の編集があるまま、別のシナリオに切り替えようとしたとき
- 未保存の編集があるまま、ウィンドウを閉じようとしたとき
- 既にある名前で新規作成・名前変更しようとしたとき

またファイル名に使えない文字は `_` に置き換わるため、`売上:A` と `売上/A` は
どちらも `売上_A.json` になる。`logic/storage.py` の `save()` が
保存先の中身を読んで別シナリオなら弾く。

### JSON はユーザーに見せない

手順は JSON で保存するが、画面には出さない。操作の追加はすべて選択とピッカーで行う。

| 項目 | 指定方法 |
| --- | --- |

### スケジュール実行は自作しない

Windows タスクスケジューラに `schtasks` で登録する。月 1 回のために常駐させない。
ただし UI 操作なので**画面がロックされていると動かない**。ログオン状態での放置が前提。

## 分かっていること

### Tkinter 製アプリは自動操作の対象にできない

Tkinter のウィジェットは UIA にも Win32 にも情報を公開しない。
`uia` では名前のない `Pane` の入れ子、`win32` では全部 `TkChild` で `title` が空になる。
そのため**練習用ダミーアプリは WinForms で作ってある**（`tools/mock_target.ps1`）。

対象アプリが同種の描画方式（Tkinter / 独自描画 / 一部の Java アプリ）だった場合、
座標・画像マッチに頼るしかなくなる。`pick.py` で先に判別すること。

### ダミーアプリは Python から起動する

`tools/mock_target.ps1` を `powershell -File` で直接叩くと日本語が壊れる。
Windows PowerShell 5.1 が BOM なし UTF-8 を ANSI として読むため。
`tools/mock_target.py` が `-EncodedCommand`（UTF-16LE）で渡して回避している。

### フォルダ選択に `askdirectory` は使えない

`pywinauto` は import 時に `sys.coinit_flags = 0`（`COINIT_MULTITHREADED`）を
設定する。そのためこのアプリのプロセスは **MTA** になり、
`tkinter.filedialog.askdirectory` が呼ぶシェルのフォルダ選択
（`SHBrowseForFolder`、**STA 必須**）が**ダイアログを出さないまま固まる**。

実測（同じスクリプトで比較）:

| | ダイアログ |
| --- | --- |
| `askdirectory` / `pywinauto` を import しない | 出る |
| `askdirectory` / `pywinauto` を import する | **出ない（固まる）** |
| `askopenfilename` / `pywinauto` を import する | 出る |

**ファイル選択は影響を受けない。** `askopenfilename` /
`asksaveasfilename` は comdlg32 の `GetOpenFileName` で、COM のモードに
関係なく開く。だから既存の［参照...］では表面化せず、フォルダ選択を
足したときに初めて出た。

`logic/folder_dialog.py` で `SHBrowseForFolderW` を直に呼び、
**STA で初期化した専用スレッド**から開くようにしてある。
結果はいつもの queue 経由でメインスレッドに戻す。開いている間も
本体の画面は固まらない。

メインスレッドから `choose_folder()` を呼ぶと、固まらずに
`FolderDialogError` になる（`CoInitializeEx` が `RPC_E_CHANGED_MODE` を
返すのを見て弾いている）。同じ罠を踏み直さないための歯止め。

親ウィンドウは渡していない。別スレッドの HWND を親にすると入力キューが
結合され、それ自体が固まる原因になるため。代わりに
`BFFM_INITIALIZED` で `SetForegroundWindow` して前面に出している。

### 共通ダイアログは UIA の走査から漏れる

「名前を付けて保存」（クラス `#32770`）は、`Desktop(backend="uia").windows()` に
**出てこない**。Win32 では確かに存在していて `visible=True` なのに、
UIA のデスクトップ配下の走査だけが取りこぼす。

そのため `logic/winfind.py` で HWND を `EnumWindows` で列挙し、
`IUIAutomation.ElementFromHandle()` から UIA 要素を作る経路を用意した。
これなら中身まで完全に見える。業務アプリは保存ダイアログや
メッセージボックスを多用するので、この経路が無いと実用にならない。

### 共通ダイアログのボタンは英語名

日本語 Windows でも、保存ダイアログのボタンは UIA 上で
`Save` / `Cancel`（`auto_id` は `1` / `2`）。題名は「名前を付けて保存」なのに
ボタンだけ英語なので、「保存」で探すと永久に見つからない。
**`auto_id` で照合すること**（`1` = OK、`2` = キャンセル）。

### ファイル名欄は win32 バックエンドで入れる

保存ダイアログのファイル名欄に UIA の `set_edit_text`（ValuePattern の
SetValue）を使うと、COM エラーで失敗する。実測で出たのは 2 種類。

```
(-2146233083, None, ...)                          タイムアウト
(-2147023673, 'この操作はユーザーによって取り消されました。', ...)
```

win32 バックエンド（`WM_SETTEXT` 経由）なら確実に入る。
入力方法を 5 通り比べて、成功したのは win32 のみだった。

欄の特定にも注意が要る。ダイアログにはアドレスバーや検索欄など Edit が
複数あり、**ファイル名欄の control_id は Windows 11 では 1001**
（よく知られた 1148 ではない。UIA 側には 1148 の要素自体が存在しない）。
`logic/runner.py` の `_set_dialog_filename()` は 1001 → 1148 → 先頭の Edit
の順に試し、**入れたあとに読み返して**一致しなければ次の候補に進む。

### 起動時に WaitForInputIdle を使わない

`Application.start()` は既定で `WaitForInputIdle` を呼ぶ。起動用の exe が
コンソールプロセスだと「指定されたプロセスは GUI プロセスでない」
（エラー 1471）で落ちる。`wait_for_idle=False` を渡し、起動できたかは
手順の「終わった合図」で判断する。

さらに、起動用の exe と画面を持つプロセスが別のことがある
（ランチャー型のアプリ）。`_rebind_to_window()` で画面を持つ PID へ
結び直している。これをしないと「アプリを閉じる」でランチャーだけ落として
本体が残る。

### schtasks の出力は UTF-8

日本語環境でも `schtasks` は UTF-8 で出力する。コンソールのコードページ
（cp932）で読むとタスク名が化け、シナリオ名と照合できなくなる
（`win_rpa_クエリ検証_実行` → `win_rpa_繧ｯ繧ｨ繝ｪ讀懆ｨｼ_螳溯｡�`）。
登録は成功しているのに一覧に出てこない、という形で表面化する。

### Tk のウィジェットに `_register` という名前を付けない

`tkinter.Misc._register(func)` を上書きしてしまい、`Toplevel.__init__` の
中（`protocol("WM_DELETE_WINDOW", ...)` の登録）で TypeError になる。
ダイアログが**生成された瞬間に落ちて、何も表示されない**。

同様に避けるべき名前: `_bind` / `_configure` / `_create` / `_displayof` /
`_do` / `_getboolean` / `_getconfigure` / `_getdoubles` / `_getints` /
`_grid_configure` / `_gridconvvalue` / `_loadtk` / `_options` /
`_register` / `_report_exception` / `_root` / `_setup` / `_substitute` /
`_windowingsystem`。

ダイアログはクラスを作った時点で落ちることがあるので、
**生成できることを検証に含めること**（`ui/` の各 Toplevel を
1 回ずつインスタンス化して `winfo_exists()` を見る）。

### デスクトップのパスは決め打ちしない

OneDrive 同期環境ではデスクトップの実体が
`C:\Users\<名前>\OneDrive\デスクトップ` に移る（この開発機がその状態）。
`Path.home() / "Desktop"` は空振りするので、
`WScript.Shell` の `SpecialFolders("Desktop")` から取る。
