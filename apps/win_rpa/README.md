# win_rpa

Windows アプリを自動操作して CSV を出力させ、複数の CSV を結合してまとめる。
アプリが CSV に出さない数値（画面にしか出ない集計結果）は、画面から読み取って
記録用の CSV に 1 行ずつ足していける。

作業のひとまとまりを**シナリオ**として何本でも保存でき、**一覧から選んで
そのとき 1 本だけ動かせる**。月 1 回の作業をスケジュール実行で無人化するのが
最初の目的だが、スケジュールに載せず手で動かすだけでも使える
（毎週・不定期の作業も、シナリオを分けておけば選んで流せる）。

作った経緯・設計判断の理由・現在地は [DEVLOG.md](DEVLOG.md) に分けてある。
**作業を再開するときはそちらから読むこと。**

## 実行

```powershell
python apps/win_rpa/main.py                        # 画面を開く
python apps/win_rpa/main.py --run 売上集計           # シナリオ 1 本だけ動かす（画面なし）
python apps/win_rpa/main.py --run 売上集計 --dry-run  # 操作せず確認だけ

python apps/win_rpa/pick.py                        # 要素ピッカー単体（下調べ用）
python tools/mock_target.py                        # 練習用ダミーアプリ
```

### エクスプローラーから起動する

`.py` をそのままダブルクリックすると、`.venv` ではなくシステム側の
Python が使われて `pywinauto` が無く失敗する。ショートカットを作る。

```powershell
python tools/make_shortcut.py win_rpa --name "Win RPA" --desktop
```

`apps/win_rpa/Win RPA.lnk`（と、デスクトップ）ができる。中身は
`.venv\Scripts\pythonw.exe` に `main.py` を渡す形で、コンソールは出ない。

起動しないときは `--console` を付けて作り直すと例外が読める。
なお `pythonw.exe` でも起動時の例外は `logs/起動エラー.log` に残り、
ダイアログにも出る（黙って何も起きない状態を避けるため）。

`.lnk` にはこの PC の絶対パスが入るので Git 管理外にしてある。
別の PC では作り直すこと。

## 使い方

1. 対象アプリを起動しておく
2. ［新規］でシナリオを作る
3. 手順一覧の右上［＋ 手順を追加］で操作を選ぶ
4. ［要素を選ぶ...］を押し、対象アプリのボタンにマウスを乗せて **F8**
5. 手順を 1 つ足すたびに［ここまで動かす］で確かめる
6. 手順が増えたら［グループ］で束ねる
7. ［保存］する。**ここまでで、いつでも動かせる状態になっている**
8. 毎月決まった日時に任せたいときだけ［スケジュール...］で登録する

### シナリオを選んで、そのとき動かす

**スケジュール登録は必須ではない。** 画面の左上にシナリオの一覧
（ドロップダウン）があり、選んで［最初から動かす］を押せば、そのシナリオ
1 本が最初から最後まで走る。

シナリオは何本でも持てるので、**作業のまとまりごとに分けておき、必要に
なったものを選んで流す**、という使い方ができる。毎月に限らず、毎週の
締め処理でも、頼まれたときだけ動かす作業でも同じように置ける。

| やりたいこと | やり方 |
| --- | --- |
| 今すぐ 1 本動かす | 一覧でシナリオを選び［最初から動かす］ |
| 動くか先に確かめる | 同じく選んで［動かさず確認］ |
| 画面を開かずに動かす | `python apps/win_rpa/main.py --run <シナリオ名>` |
| 毎月決まった日時に任せる | ［保存］→［スケジュール...］ |

登録済みのスケジュールがあっても、手で動かすことはいつでもできる。
両者は独立していて、同じシナリオを指しているだけ。

### シナリオ 1 本を、ダブルクリックで動かす

よく動かすシナリオは、そのシナリオを指すショートカットを作っておくと
**ダブルクリックだけで走る**（画面は出ず、結果は `logs/` に残る）。

```powershell
python tools/make_shortcut.py win_rpa --name "売上集計を実行" --args "--run 売上集計" --desktop
```

`--args` に渡した内容がそのまま `main.py` に届く。シナリオごとに名前を
変えて作れば、デスクトップに「作業ごとのボタン」が並ぶ形になる。

- シナリオ名に空白を含めない（`--args` の内容は空白で区切られる）
- 動かなかったら `--console` を付けて作り直すと、出た例外が読める

### 実行ボタンは 4 つ

違いは**アプリを操作するかどうか**と、**どこからどこまでを動かすか**。

| ボタン | 操作する | 範囲 |
| --- | --- | --- |
| ［動かさず確認］ | **しない** | 全部。対象が見つかるかだけ調べる |
| ［この手順だけ動かす］ | する | 選んだ手順 1 つだけ |
| ［ここまで動かす］ | する | 最初から、選んだ手順まで |
| ［最初から動かす］ | する | 全部（本番と同じ） |

［この手順だけ動かす］は**前の手順を動かさない**ので、対象アプリは自分で
開いておくこと。要素は記録されたウィンドウ題名から探すので、起動済みなら
見つかる。直した手順 1 つだけを試したいときに使う。

このときだけ、未入力の検証も**その手順しか見ない**。組み立て途中の他の手順が
埋まっていなくても、今直した 1 つを試せる。

### まだベータ版であることを画面に出す

ツールバーの右端に **⚠ ベータ版 0.9.2** と出る。押すと「について」の
小窓が開き、何をするソフトかと、何に気をつけるべきかが読める。

実機（対象の業務アプリ）での確認が済んでいない状態を、画面を見ただけで
分かるようにしてある。**確認が済んだら `logic/appinfo.py` の
`IS_BETA` を False にする。** 色と警告が消え、表示が
「バージョン 0.9.2」に変わる。

版と説明の文言は `logic/appinfo.py` の 1 か所に置いてある（ツールバー・
「について」の小窓・実行ログの 1 行目が同じ所を見る）。**出来ることを
足したら版も上げる。** 実行ログに出る版で、対象 PC で動いているのが
どのビルドかを切り分けるため。

### 操作は分類から選ぶ

［＋ 手順を追加］は分類ごとの入れ子になっている。

| 分類 | 入っているもの |
| --- | --- |
| アプリを操作する | 起動 / ボタンを押す / 文字を入力 / チェック / 一覧から選ぶ / キーを押す / メニューから選ぶ / ウィンドウを前面に出す / メッセージに応じる / 閉じる |
| ファイルとフォルダ | 保存ダイアログ / 開くダイアログ / フォルダを作る / 保存先を選ぶ / コピー／移動 |
| 確認する | 画面の表示 / ファイルができたか / 画面を保存する / 表示された数値を記録する |
| その他 | CSV をまとめる / しばらく待つ / 別のプログラムを実行する / 用意した処理を実行する |

画面上の要素を直接つかめない操作は、次の 4 つで埋める。

| 操作 | 使う場面 |
| --- | --- |
| キーを押す | ボタンが無い操作。Enter で確定、Tab で次の欄、Ctrl+S で保存。キーは一覧から選ぶ（`{ENTER}` のような書き方は覚えなくてよい） |
| メニューから選ぶ | 「ファイル > エクスポート」のようにメニューバーを順にたどる。開かないと存在しない項目を 1 手順で扱える |
| ウィンドウを前面に出す | 操作する画面を手前に出し、以降の手順の対象をそのウィンドウに移す。別ウィンドウを開くアプリで使う |
| メッセージに応じる | 「よろしいですか？」の確認に答える。**無人実行ではこれが無いと止まったまま朝を迎える。** 題名を空にすると、出ているメッセージをそのまま対象にする。既定では出ていなければ飛ばす |

「ボタンを押す」には［押し方］があり、ダブルクリックと右クリックも選べる。

分類は `logic/actions.py` の各 `ActionSpec` に `category=` で書いてある。
操作を増やしても `ui/` は触らない。

**前に必要な手順がある操作は、理由がその場に出る。**
「CSV をまとめる」は、手前に「フォルダを作る」か「保存先フォルダを選ぶ」が
あるか、この手順の「まとめる場所」を指定するかのどちらかが要る。
どちらも無いまま保存・実行しようとすると、一覧に ⚠ が付いて理由が出る。

### 手順をグループで束ねる

手順一覧はツリーになっていて、手順を**グループ**にまとめられる。

一覧で手順を選び（Ctrl / Shift で複数選べる）、［グループ］→
［選んだ手順をまとめる...］で名前を付ける。見出しをクリックすると
折りたためる。

| したいこと | やり方 |
| --- | --- |
| まとめる | 手順を選んで［グループ］→［選んだ手順をまとめる...］ |
| 別のグループへ移す | 手順を選んで［グループ］→［別のグループへ移す...］ |
| グループから出す | 手順を選んで［グループ］→［グループから出す］ |
| 名前を変える | 見出しを選んで［グループ］→［グループ名を変更...］ |
| グループごと動かす | 見出しを選んで ↑ ↓ |
| 手順を隣のグループへ | 手順を選んで、境目で ↑ ↓ をもう一度押す |

**グループは見出しでしかない。** 実行順は今まで通り上から 1 本の直線で、
分岐も繰り返しもない。長いシナリオを読めるようにするためだけのもの。

### ファイル操作

| 操作 | 何をするか |
| --- | --- |
| フォルダを作る | 出力先フォルダを作る。名前は年月日などの型から自動で決まる |
| 保存先フォルダを選ぶ | これ以降の手順の基準フォルダを切り替える |
| ファイルをコピー／移動する | 出来上がった CSV を別フォルダへ運ぶ |
| 「ファイルを開く」に応じる | 対象アプリが出す開くダイアログにファイル名を入れて開く |

**フォルダ名は打たずに選ぶ。** ［型］に年月日の並べ方が入っている。

| 選ぶもの | 出来上がる名前 |
| --- | --- |
| 年月 | `202608` |
| 年月（区切りあり） | `2026-08` |
| 年月日 | `20260828` |
| 年 の下に 月 | `2026\08`（フォルダが 2 段になる） |
| 前月 | `202607` |
| シナリオ名＋年月 | `売上集計_202608` |

選ぶと、その下に**実際に出来上がるフルパス**が出る。既にあるかどうかも
そこに出るので、毎月同じフォルダに上書きしていないか確認できる。
先頭に文字を足したい場合は欄に直接書き足せる（`月次_{yyyymm}` など）。

「フォルダを作る」「保存先フォルダを選ぶ」を通すと、**それ以降の手順の
保存先が切り替わる**。ファイル名だけを書いた項目（`売上_{yyyymm}.csv` など）は
その時点の保存先を基準に解決される。

コピーの対象も打たずに選ぶ。［型］に「すべてのファイル」「CSV すべて」
「今月分の CSV」などが入っていて、選ぶと**今そこに何件あるか**が下に出る。
0 件のまま気づかず組んでしまうのを防ぐため。

#### 更新日で絞る

ファイル名に日付が入っていない出力もある。そのときは `更新日で絞る` で、
**ファイルの更新日時**を見て対象を選ぶ。ここも日付は打たず、型から選ぶ。

| 選ぶもの | 8/31 に動かすと |
| --- | --- |
| 指定なし（すべて） | 絞らない（既定） |
| **先月（1 日〜末日）** | 7/1 00:00 〜 7/31 23:59 |
| 今月（1 日〜今日） | 8/1 00:00 〜 8/31 23:59 |
| 今日 / 昨日 | 8/31 / 8/30 の 1 日ぶん |
| 直近 7 日 / 直近 30 日 | 8/25 〜 8/31 / 8/2 〜 8/31 |
| 期間を指定する | 年・月・日を選んだ範囲（両端を含む） |

選ぶと、その下に**今日動かすといつからいつまでになるか**が出る。
「先月」を選んで 7 月になっているかを、その場で目で確かめられる。

年またぎ（1 月に「先月」＝前年 12 月）とうるう年の末日も型の側で解決する。
`{prev_yyyymm}` のような名前での絞り込みと違い、**ファイル名に日付が
無くても効く**。名前と更新日の両方で絞りたいときは、両方を指定すればよい
（`対象のファイル` で名前、`更新日で絞る` で日付）。

実行すると「`*.csv` は 6 件。そのうち更新日が 先月 のものは 3 件です」と
ログに出る。絞った結果 `最低件数` を下回ったときは、**絞る前の件数と
選んでいる範囲**をエラーに出す（範囲の選び間違いと、そもそも出力が
無いのとを切り分けるため）。

`最低件数` を下回ると失敗にする。0 件を黙って次の手順に渡さないための歯止め。

`同じ名前のとき` の既定は**飛ばす**。毎月動かすので、行き先に前月分が残って
いても止まらず、かつ黙って消さないようにしてある。上書きを選ぶと
行き先のファイルは消える。

### CSV をまとめる（特殊な手順）

想定している使い方は、**日単位で貯まった CSV を 1 か月ぶん、
1 本の連続データにする**こと。

```
日次/  ← 対象アプリが毎日 1 本ずつ吐く
    売上_20260801.csv
    売上_20260802.csv        1  フォルダを作る          → 日次/202608
    ...                      2  ファイルをコピーする    → 31 本を入れる
    売上_20260831.csv        3  CSV をまとめる          → 月次_202608.csv
```

**まとめる場所の中の CSV を全部**読み込み、日時の古い順に並べ替えて
1 つにまとめ、**同じフォルダに**置く。

| 項目 | 内容 |
| --- | --- |
| まとめる場所 | ［参照...］で選ぶ。空にすると手前の「フォルダを作る」で作った場所（それが無ければその時点の保存先） |
| できあがる名前 | ［型］から選ぶ（`まとめ_{yyyymmdd}.csv` など）。`.csv` は自動で付く |
| 元ファイル名の列を足す | どの CSV から来た行かを末尾の列に残す |
| 最低行数 | これを下回ると失敗にする |

まとめる場所を指定すれば、**手前に「フォルダを作る」が無くても動く**。
既にある月次フォルダを選んで、まとめ直すだけの 1 手順シナリオが作れる。

フォルダの中のどれを対象にするかは選ばせない。まとめる場所に入っている
ものが対象、という以外の解釈が無いため。

**並べ替えの列は自動で見つける。** 見出しの**先頭 4 列**の中から、
名前に「日時」「日付」「年月日」「date」などが入っている列を先に試し、
無ければ中身を読んで日時として通るかで判断する。使った列は実行ログに出る。

**時刻まで見て並べる。** 日単位のファイルを 1 か月ぶんまとめる用途では、
時刻を落とすと同じ日の中が元ファイルの並び順のまま残ってしまうため。

読める書き方は次のとおり。ファイルごとに違っていても混ぜて並べられる。

```
2026-08-28 10:30:00    2026/8/5 9:07     2026-08-28T10:30:00
2026-08-28 10:30:00.5  20260828 07:05:00  20260828070500
2026年8月28日 14時05分
2026-08-28   2026/8/5   20260828   2026年8月28日   2026.08.28   （日付だけも可）
2026-08      2026/08                                            （年月だけも可）
```

- 日時として読めなかった行は**捨てずに末尾**へ回す
- 先頭付近に日時の列が無ければ、読み込んだ順のままにして警告を出す
- できあがるファイル自身は対象から除く（2 回目に動かしても行が倍にならない）

実行ログに**まとまった期間**が出る。1 か月ぶんが揃っているかを、
ファイルを開かずに確かめられる。

```
[info]   「日時」の古い順に並べ替えました
[info]   2026-08-01 10:00:00 〜 2026-08-31 17:00:00 の 93 行
[ok]    31 件を 93 行にまとめました（...\202608\月次_202608.csv）
```

**まとめる先が決まらない組み方は、保存前に止まる。**「まとめる場所」が
空で、手前に「フォルダを作る」も「保存先フォルダを選ぶ」も無い場合、
一覧に ⚠ が付き、実行時は対象アプリを起動する前に止まる。

### 表示された数値を記録する

**対象アプリが CSV に出してくれない値**（画面にしか出ない集計結果、合計金額、
件数）を拾って、記録用の CSV の**末尾に 1 行足す**。動かすたびに 1 行増えるので、
月をまたいでも 1 本の連続データになる。

```
日時,シナリオ,項目,値,元の表示
2026-09-01 10:00:03,売上集計,件数,237,集計完了（237 件）
2026-09-01 10:00:06,売上集計,合計金額,1234567,"1,234,567"
2026-10-01 10:00:04,売上集計,件数,251,集計完了（251 件）
```

| 項目 | 内容 |
| --- | --- |
| 数値が出ている場所 | ピッカーで選ぶ（他の手順と同じ） |
| 読み取り方 | 表示から読む／選択してコピーする／クリックしてからコピーする |
| 項目名 | 「項目」列に入る名前。1 つのファイルに複数の値を記録できる |
| 記録するファイル | ［型］から選ぶ。**毎回同じファイルに足す**のが基本 |
| 数値だけを取り出す | 「1,234 件」から `1234` を取り出す（既定は入） |

- 列は固定（日時 / シナリオ / 項目 / 値 / 元の表示）。**先頭が日時**なので、
  出来たファイルはそのまま「CSV をまとめる」の並べ替えに乗る
- `元の表示` に読み取った文字がそのまま残る。`1234` が
  「1,234 件」から来たのか別の数字から来たのかを、後から確かめられる
- 数値が取り出せなければ**失敗にする**。0 で埋めない
  （処理が終わる前に読んだ、指す場所を間違えた、を黙って記録しないため）
- 記録に必要な列が無いファイルを指していたら、**書かずに止まる**。
  対象アプリの出力や「CSV をまとめる」の結果と同じ名前を指してしまった場合に、
  列のずれた行を足して壊さないため

**［型］に日付で変わる名前を出していない。** 動かすたびに別のファイルが
出来ると貯まらないため。年ごと・月ごとに分けたいときだけ
`記録_{yyyy}.csv` `記録_{yyyymm}.csv` を選ぶ。

欄の下に**今そのファイルが何行あるか**が出る。指定を間違えて毎回別の
ファイルを作っている（行が増えていない）ことに、実行する前に気づける。

#### 読み取り方の選び方

| 読み取り方 | 何をするか | 使う場面 |
| --- | --- | --- |
| 表示から読む | UIA から文字を読む。操作しない | まずこれ |
| 選択してコピーする | 対象を選んで Ctrl+C。中身をクリップボードから受け取る | 表示から読めない欄 |
| クリックしてからコピーする | クリックしてから Ctrl+C（全選択しない） | 一覧のセル |

一覧（表）のセルで「選択してコピーする」を使うと**表ぜんぶがコピーされる**。
セルを 1 つだけ取りたいときは「クリックしてから」を選ぶ。

コピーを使うと**クリップボードの中身が入れ替わる**（人が作業中の PC で
手動実行するときは注意）。読む前に必ず空にしてから Ctrl+C を送るので、
コピーが効かなかったときに前の中身を「読み取った値」として記録することはない。

確認実行（動かさず確認）ではクリップボードに触らない。対象が見つかるかと、
どのファイルに何行目として足すかだけを出す。

### スケジュールの登録

［スケジュール...］を開き、実行する日と時刻を決めて［登録する］を押す。
Windows のタスクスケジューラに登録され、アプリを開いていなくても動く。

登録されるのは 2 つ。

| タスク名 | 内容 |
| --- | --- |
| `win_rpa_<シナリオ名>_実行` | 本番。CSV を出力して結合する |
| `win_rpa_<シナリオ名>_確認` | 確認実行。操作せず、要素が見つかるかだけ調べる |

確認のほうを本番より前の日時にしておくと、対象アプリの更新で壊れていた
場合に事前に気づける。月 1 回しか動かないので、当日に初めて知るのは遅い。

画面下部に**全シナリオの登録一覧**が出る（シナリオ／種類／実行日時／次回）。
行を選んで［選んだものを削除］で個別に消せる。開いているシナリオ以外の
ものも消せるので、取り残されたタスクをここで片付けられる。

登録済みの日時は開いたときに入力欄へ読み込まれる。既定値に戻ると
「今どう登録されているか」が分からないまま上書きしてしまうため。

**シナリオを削除・改名すると、スケジュールも自動で追従する。**
削除なら解除、改名なら同じ日時で新しい名前に付け替える。これを怠ると、
実体の無いシナリオを毎月起動しては失敗し続けるタスクが残る。

**画面がロックされていると動かない。** UI を操作するため、実行時刻に PC が
ログオン状態である必要がある。ここは自動化しきれない。

手順を全部組んでから通しで試すと、どこが悪いか分からなくなる。
**1 手順ごとに［ここまで動かす］**で確かめながら進めること。

実行日の前日に確認実行を仕込めるようにしてある。
月 1 回しか動かさないので、当日に初めて壊れているのを知るのを避けるため。

## 設計方針

### 記録するのは座標ではなく「要素の同一性」

マクロレコーダー的にマウス座標を記録すると、ウィンドウ位置が変わった時点で壊れる。
クリック対象の **AutomationId / 名前 / 種類 / 構造上の位置**を採取して残し、
実行時はそれで要素を探す。

照合は次の順に試し、前段が外れたら次に落ちる。

1. `auto_id`（最も安定）
2. `name` + `control_type`
3. `help_text`（ツールチップ）
4. `legacy_name`（古い形式の名前）
5. `index_path`（同じ種類の中で何番目か）

3・4 はアイコンだけのツールバーボタン用。5 だけになる要素は
記録する前に確認を出し、実行時も毎回警告する。詳しくは
「名前のないボタンの探し方」を参照。

複数持たせるのは、アプリが更新されて片方が変わっても動き続けるようにするため。
`class_name` は記録するが**照合には使わない** — WinForms のクラス名は
`WindowsForms10.BUTTON.app.0.22c71e1_r8_ad1` のように実行ごとに変わる
ハッシュを含むため。

### ウィンドウの題名は完全一致

「終わった合図」の「ウィンドウが出る」は、最上位ウィンドウを列挙して
題名を**完全一致**で照合する。部分一致も前方一致もしない。

そのため題名が実行のたびに変わるウィンドウには使えない
（`売上管理システム - 2026年08月`、`売上.csv - メモ帳` など）。
その場合は「要素が現れる」「要素が押せるようになる」
「表示に文字が現れる」を使う。

打ち間違いで永久に見つからない手順ができるのを防ぐため、
題名は今開いているウィンドウの一覧から選ぶ形にしてある。
一覧には UWP の隠しウィンドウが混ざるので、`DWMWA_CLOAKED` で除いている
（`IsWindowVisible` では除けない）。

### 待ちは手順の一部として記録する

各ステップに「次に何が現れたら成功か」（`wait_for`）を持たせる。
`sleep` で書くと、実行環境や当日の負荷で必ずいつか足りなくなる。

「しばらく待つ」という手順も用意はしてあるが、**合図で待てないときの
最後の手段**として置いている。中止を押してから最大 5 分待たされないよう、
一息に `sleep` せず 0.4 秒ずつ刻んで中止を見ている。

### メニューを探す範囲はプロセスに絞る

開いたメニューは、アプリの画面とは別の最上位ウィンドウとして出る。
そのため「メニューから選ぶ」は要素の照合（`_resolve`）ではなく、
ウィンドウを列挙して `MenuItem` を名前で探している。

探す範囲は**起動したプロセスが持つウィンドウだけ**。デスクトップ全体を
走査すると、画面上のすべてのアプリの UI ツリーをたどることになり、
現実的な時間で終わらない。

そのプロセスがウィンドウを 1 つも持たないとき（ランチャー型のアプリ。
起動用の exe が別プロセスの本体を立ち上げるもので、メモ帳がこの形）
だけ、いま手前にあるウィンドウのプロセスに広げる。無条件に広げないのは、
**対象アプリの起動に失敗したときに、関係の無いアプリのメニューを
操作してしまう**ため。アプリを掴んでいることを条件にしてある。

そのため「メニューから選ぶ」は、先に「アプリを起動する」か
「ウィンドウを前面に出す」が要る。無ければその場で理由を出して止まる。

### 画面を保存する

失敗したときは今までどおり自動で画面を残す。加えて、成功した経過にも
証跡を残せるよう「画面を保存する」を手順として置けるようにした。
月に 1 回しか動かないので、「本当にこの内容で出力したか」を後から
見られることに価値がある。

撮影は PIL の `ImageGrab`（全モニタ）で行う。pywinauto の
`capture_as_image` はウィンドウ 1 つ分を撮るもので `Desktop` には無く、
失敗時の記録はこれを呼んでいたため、**実際には 1 枚も残っていなかった**。

### 前提のある手順は、置く前に止める

「CSV をまとめる」は、まとめる場所を自分で持たない組み方もできる
（空にすると手前の手順が決めた場所を使う）。そのまま置けてしまうと、
実行して初めて成り立たないことに気づく。月 1 回しか動かさないので、
それは遅すぎる。

前提は `ActionSpec` の**宣言側**に書く。

- `requires` — 手前にあれば満たされるアクション名。どれか 1 つでよい
  （`("make_folder", "set_work_dir")`）
- `requires_unless` — この項目が埋まっていれば `requires` は問わない
  （`"folder"`＝「まとめる場所」）

効かせる場所は 2 か所。

1. 一覧と保存前の検証 — `Scenario.step_problems()` が ⚠ を付ける
2. 実行の開始時 — **対象アプリを起動する前に**止める

2 が要るのは、8 手順進んでから「先にフォルダを作る手順が要る」と言われても
遅いため。1 だけだと、種類のドロップダウンで後から切り替えた場合に漏れる。

［＋ 手順を追加］では止めない。`requires_unless` のある操作は、置いてから
場所を指定すれば成り立つので、置く前に塞ぐと指定する機会が無くなる。

### 検証ステップを手順に含める

「CSV が出来て、想定の行数がある」ところまでが手順。ここが無いと、
空ファイルを黙って結合して終わる。

### 分岐とループは入れない

`if` / `while` / 変数を入れると、手順一覧が入れ子のツリーになり、
条件式を書く UI とデバッグ機能が要る。月次ルーティンは平坦な直線で書ける。
特殊処理が必要になったら `run_python` アクション（用意したスクリプトを呼ぶ）で吸収する。

### グループは見出しだけ

手順が 20 を超えると一覧が読めなくなるので、ツリーで束ねられるようにした。
ただし**入れ物は作っていない**。`Step.group` という名札を 1 つ足しただけで、
`Scenario.steps` は今まで通り 1 本のリスト。同じ名札が隣り合っている区間を
`Scenario.groups()` が塊として返し、画面がそれを親ノードとして描く。

こうすると実行エンジンも `upto`（ここまで動かす）も保存形式も変わらない。
入れ子の入れ物を持つと、ここに「入れ子の何番目まで実行」という概念が
生まれ、分岐を入れないと決めた意味が薄れる。

同じ名札が離れて置かれると見出しが 2 つに割れるため、グループ操作の直後だけ
`normalize_groups()` で先に出たほうへ寄せる。↑↓ の入れ替えでは呼ばない
（並べ替えた結果が勝手に動くと、何が起きたか分からなくなるため）。

### 保存先は実行中に動く

「フォルダを作る」「保存先フォルダを選ぶ」は `Runner` の作業フォルダを
差し替える。相対指定のファイルはその時点の作業フォルダを基準に解決するので、
差し込み変数の `{work_dir}` も同時に更新する（片方だけ変えると食い違う）。

確認実行では**フォルダは作らないが、保存先の切り替えは行う**。
切り替えないと、確認実行のときだけ以降のパスが本番と違うものになり、
確認の意味が無くなるため。

### ファイルを消す操作は入れない

削除アクションは用意しない。月 1 回・無人で動くものが誤って消すと、
気づくのが 1 か月後になる。片付けは人の手でやる。

コピーの「同じ名前のとき」の既定も**飛ばす**にしてある。上書きは
選んだときだけ。

### シナリオは何本でも持てる

`scenarios/` に 1 シナリオ 1 ファイルで貯まり、上部のドロップダウンで
切り替える。月次・週次・別システム向けを並べて持てる。

**スケジュールはシナリオの属性ではない。** タスクスケジューラ側に別途
登録するもので、シナリオ自体は「選んで動かせる作業のまとまり」でしかない。
だから登録していないシナリオも同じように動かせるし、登録済みのものを
手で動かすこともできる。月次に縛られない作りは、この分離から来ている。

取り違えを防ぐため、次の場面で必ず確認を出す。月 1 回しか触らないので、
黙って消えると気づくのが 1 か月後になるため。

- 未保存の編集があるまま、別のシナリオに切り替えようとしたとき
- 未保存の編集があるまま、ウィンドウを閉じようとしたとき
- 既にある名前で新規作成・名前変更しようとしたとき

またファイル名に使えない文字は `_` に置き換わるため、`売上:A` と `売上/A` は
どちらも `売上_A.json` になる。`logic/storage.py` の `save()` が
保存先の中身を読んで別シナリオなら弾く。

### JSON はユーザーに見せない

手順は JSON で保存するが、画面には出さない。操作の追加はすべて選択とピッカーで行う。

| 項目 | 指定方法 |
| --- | --- |
| 対象の要素 | ピッカー（マウスを乗せて F8） |
| 操作の種類 | 要素の種類から自動推定（Button → 押す、Edit → 文字入力…） |
| 完了条件 | ドロップダウン |
| ウィンドウの題名 | 今開いているウィンドウの一覧から選ぶ |
| 入力値 | テキスト欄＋「差し込み」ボタン（今年月・前月など） |
| 起動するアプリ | デスクトップ／スタートメニューのショートカット一覧から選ぶ（一覧に無ければ［ファイルを直接選ぶ...］） |
| フォルダ名 | ［型］（年月・年月日・年の下に月…）＋［参照...］ |
| まとめて扱うファイル | ［型］（すべて・CSV すべて・今月分…）＋［1 つ選ぶ...］ |
| 移す先のグループ | 今あるグループの一覧から選ぶ |

### スケジュール実行は自作しない

Windows タスクスケジューラに `schtasks` で登録する。月 1 回のために常駐させない。
ただし UI 操作なので**画面がロックされていると動かない**。ログオン状態での放置が前提。

## 分かっていること

### 名前のないボタンの探し方

アイコンだけのツールバーボタンは、UIA の Name も AutomationId も空のことがある。
そのまま拒否すると手順に入れられないので、**名前になるものを 4 通り探す**。

| 段 | 見るもの | 備考 |
| --- | --- | --- |
| 1 | AutomationId | いちばん安定 |
| 2 | 名前（UIA の Name） | |
| 3 | ツールチップ（UIA の HelpText） | アイコンだけのボタンはここに説明がある |
| 4 | 古い形式の名前（LegacyIAccessible） | Win32 / MFC のツールバーはこちらだけ持つことがある |
| 5 | 構造上の位置（index_path） | 最後の手段。**ボタンが増減すると隣を操作する** |

3・4 は `child_window()` で指定できないので、その段に落ちたときだけ
`descendants()` を自分で見て回る。1・2 が当たれば走査は起きない。

5 だけになる要素は、ピッカーが**記録する前に確認を出す**。使えなくはないが、
対象アプリの更新で黙って別のものを押す危険があるため。実行時も毎回警告を出す
（後からログで追えるようにするため）。

### 入力欄の `window_text()` は、中身ではなくラベルを返す

WinForms の入力欄は、UIA の Name が**隣のラベルの文字**になる。
「合計金額」というラベルの右の欄を `window_text()` で読むと `合計金額` が
返り、金額そのものは取れない（実測。ダミーアプリの `txtTotal` で確認）。

中身は `LegacyIAccessible` の `Value`（`legacy_properties()["Value"]`、
`get_value()` でも同じ）に入っている。そのため「表示された数値を記録する」は、
**種類によって名前と値のどちらを先に読むかを変えている**
（`Edit` / `Document` / `ComboBox` / `Spinner` は値が先）。

ラベル（`Text`）は逆で、Name に文字が入り Value は空。片方だけを見る作りに
すると、どちらかで必ず取り逃す。

### 1 行の入力欄では Ctrl+A が効かない

WinForms の 1 行 TextBox に Ctrl+A を送っても選択されない（実測）。
何も選択されていない状態で Ctrl+C を送るとクリップボードは空のままになる。

「選択してコピーする」は、Ctrl+A で駄目なら **Ctrl+Home → Ctrl+Shift+End**
（先頭から末尾まで選ぶ）に落として、もう一度 Ctrl+C を送る。
落ちたことは実行ログに残す。

| 送ったもの | ReadOnly の 1 行 TextBox |
| --- | --- |
| Ctrl+A → Ctrl+C | **空のまま** |
| Ctrl+Home → Ctrl+Shift+End → Ctrl+C | 取れる |
| ダブルクリック → Ctrl+C | 取れる（単語単位なので桁区切りで切れる恐れ） |
| クリック → Ctrl+C | 空のまま（選択されていないため） |

Ctrl+A を先に試すのは、一覧や独自コントロールではそちらしか効かないため。

### exe にすると `win32timezone` が足りない

pywin32 は COM の日時（FILETIME）変換で `win32timezone` を**遅延 import** する。
import 文としてコードに現れないので PyInstaller の解析に出ず、同梱されない。
ショートカットの解決が **exe でだけ** `ModuleNotFoundError` で落ちる。

`tools/build.py` の `_HIDDEN_IMPORTS` で `--hidden-import` を渡している。
同種の同梱漏れに当たったら、そこに足すこと。

### 配布フォルダに要らないものが入る

逆に、**一度も通らない経路のものが丸ごと入る**。PyInstaller は
「import 文がある」だけで拾うため。対象 PC へコピーする時間に直接効くので、
`tools/build.py` の `_EXCLUDES` で外している。

| 外したもの | 大きさ | 外してよい理由 |
| --- | --- | --- |
| `numpy` | 26.7 MB | `comtypes` の numpy 連携（COM の SAFEARRAY を ndarray で受け渡す）。`comtypes.npsupport.enable_numpy_interop()` を呼んだときだけ動くもので、pywinauto は呼ばない |
| `PIL.AvifImagePlugin` | 7.5 MB | Pillow の AVIF 対応（`_avif.pyd`）。保存するのは PNG だけ。画像プラグインの読み込みは PIL 側が `ImportError` を握るので他の形式に影響しない |

これで **64.1 MB → 28.1 MB**（963 ファイル）になった。

**外す前に、本当に呼ばれないか確かめること。** 見た目が同じくらい無駄に
見えても、`pythonwin`（`win32ui`、1.1 MB）は外せない。
`pywinauto/base_wrapper.py` が先頭で `import win32ui` している。

残っているものの内訳は次のとおりで、これ以上はほとんど削れない。

| 中身 | 大きさ | 用途 |
| --- | --- | --- |
| `_tcl_data` ほか tcl / tk | 6.0 MB（830 ファイル） | 画面（Tkinter）。**ファイル数の 86 % がこれ** |
| `python310.dll` | 4.3 MB | Python 本体 |
| `win_rpa.exe` + `base_library.zip` | 5.2 MB | このアプリと標準ライブラリ |
| `PIL` | 3.2 MB | 画面の保存 |
| `libcrypto` / `libssl` | 4.0 MB | `ssl`。通信はしないので外せるが、`urllib` 経由で踏む経路が残っていないか確かめきれていないため触っていない |
| pywin32（`win32*` / `pythonwin`） | 3.0 MB | ショートカットの解決と `pywinauto` |

### コピーが遅いのは大きさよりファイル数

削っても **963 ファイル**残る。うち 830 は tcl のスクリプトで、
これは Tkinter を使う限り消せない。小さいファイルを大量にコピーするのは、
同じ容量の 1 ファイルより桁で遅い（特にネットワーク越し）。

**フォルダのまま運ばず、zip にして 1 ファイルで渡す。** 圧縮すると
12.6 MB になる。

```powershell
Compress-Archive -Path build\dist\win_rpa -DestinationPath win_rpa.zip -Force
```

`--onefile`（1 ファイルの exe）も 12.7 MB になるが、**採らない**。
この PC で試したところ、コンソールのあるプロセス（PowerShell の `&`、
Python の `subprocess`）から起動すると PyInstaller のブートローダーが
`Security validation failure: parent process has different executable!` の
ダイアログを出して止まった。エクスプローラーからのダブルクリックと
`Start-Process` では動くが、起動のしかたで結果が変わるものを
月 1 回・無人で動かす場所には置けない。

### 起動用のファイルは exe とは限らない

業務アプリが `.kww` のような**固有拡張子のファイル**で起動されることがある。
これをそのまま `Application.start()` に渡しても動かない。中身が
CreateProcess で、**関連付けもショートカットも解決しない**ため。

`logic/launch.py` が、Windows がダブルクリックでやっていることを自前でたどる。

| ファイルの中身 | たどり方 | 結果 |
| --- | --- | --- |
| exe / bat / cmd / com | そのまま | 実行ファイル |
| シェルリンク（`.lnk` と同じ形式） | `IShellLink` でリンク先と引数を読む | ショートカット |
| それ以外 | レジストリの関連付けから起動コマンドを読む | 関連付け |

**ショートカットかどうかは拡張子ではなく中身で判断する。** 先頭 20 バイトが
ヘッダ長 `0x4C` ＋ `CLSID_ShellLink` ならシェルリンク。

`WScript.Shell.CreateShortcut` は使えない。`.lnk` / `.url` 以外のパスを渡すと
**COM エラーで拒否される**（「ショートカットのパス名は .lnk または .url で
終わらなければなりません」）。`IShellLink` + `IPersistFile` は中身しか見ないので
拡張子を問わない。

関連付けは `HKCR` だけ見ると外れる。「プログラムから開く」で選び直されていると
`HKCU\...\Explorer\FileExts\<拡張子>\UserChoice` が優先されるため、そちらを先に見る。
起動コマンドの `%1` / `%L` / `%*` は自前で展開する。

`os.startfile`（ShellExecute）に投げれば Windows が全部やってくれるが、それは
採らなかった。**起動したプロセスの PID が返らない**ので `Runner` が `self._app` を
保持できず、「アプリを閉じる」が窓の題名頼みになる。exe と引数まで落としておけば
今までどおり `Application.start()` が使え、画面にも実際に走るコマンドを出せる。

### Tkinter 製アプリは自動操作の対象にできない

Tkinter のウィジェットは UIA にも Win32 にも情報を公開しない。
`uia` では名前のない `Pane` の入れ子、`win32` では全部 `TkChild` で `title` が空になる。
そのため**練習用ダミーアプリは WinForms で作ってある**（`tools/mock_target.ps1`）。

対象アプリが同種の描画方式（Tkinter / 独自描画 / 一部の Java アプリ）だった場合、
座標・画像マッチに頼るしかなくなる。`pick.py` で先に判別すること。

### ダミーアプリは Python から起動する

`tools/mock_target.ps1` を `powershell -File` で直接叩くと日本語が壊れる。
Windows PowerShell 5.1 が BOM なし UTF-8 を ANSI として読むため。
`tools/mock_target.py` が `-EncodedCommand`（UTF-16LE）で渡して回避している。

### フォルダ選択に `askdirectory` は使えない

`pywinauto` は import 時に `sys.coinit_flags = 0`（`COINIT_MULTITHREADED`）を
設定する。そのためこのアプリのプロセスは **MTA** になり、
`tkinter.filedialog.askdirectory` が呼ぶシェルのフォルダ選択
（`SHBrowseForFolder`、**STA 必須**）が**ダイアログを出さないまま固まる**。

実測（同じスクリプトで比較）:

| | ダイアログ |
| --- | --- |
| `askdirectory` / `pywinauto` を import しない | 出る |
| `askdirectory` / `pywinauto` を import する | **出ない（固まる）** |
| `askopenfilename` / `pywinauto` を import する | 出る |

**ファイル選択は影響を受けない。** `askopenfilename` /
`asksaveasfilename` は comdlg32 の `GetOpenFileName` で、COM のモードに
関係なく開く。だから既存の［参照...］では表面化せず、フォルダ選択を
足したときに初めて出た。

`logic/folder_dialog.py` で `SHBrowseForFolderW` を直に呼び、
**STA で初期化した専用スレッド**から開くようにしてある。
結果はいつもの queue 経由でメインスレッドに戻す。開いている間も
本体の画面は固まらない。

メインスレッドから `choose_folder()` を呼ぶと、固まらずに
`FolderDialogError` になる（`CoInitializeEx` が `RPC_E_CHANGED_MODE` を
返すのを見て弾いている）。同じ罠を踏み直さないための歯止め。

親ウィンドウは渡していない。別スレッドの HWND を親にすると入力キューが
結合され、それ自体が固まる原因になるため。代わりに
`BFFM_INITIALIZED` で `SetForegroundWindow` して前面に出している。

### 共通ダイアログは UIA の走査から漏れる

「名前を付けて保存」（クラス `#32770`）は、`Desktop(backend="uia").windows()` に
**出てこない**。Win32 では確かに存在していて `visible=True` なのに、
UIA のデスクトップ配下の走査だけが取りこぼす。

そのため `logic/winfind.py` で HWND を `EnumWindows` で列挙し、
`IUIAutomation.ElementFromHandle()` から UIA 要素を作る経路を用意した。
これなら中身まで完全に見える。業務アプリは保存ダイアログや
メッセージボックスを多用するので、この経路が無いと実用にならない。

### 共通ダイアログのボタンは英語名

日本語 Windows でも、保存ダイアログのボタンは UIA 上で
`Save` / `Cancel`（`auto_id` は `1` / `2`）。題名は「名前を付けて保存」なのに
ボタンだけ英語なので、「保存」で探すと永久に見つからない。
**`auto_id` で照合すること**（`1` = OK、`2` = キャンセル）。

### ファイル名欄は win32 バックエンドで入れる

保存ダイアログのファイル名欄に UIA の `set_edit_text`（ValuePattern の
SetValue）を使うと、COM エラーで失敗する。実測で出たのは 2 種類。

```
(-2146233083, None, ...)                          タイムアウト
(-2147023673, 'この操作はユーザーによって取り消されました。', ...)
```

win32 バックエンド（`WM_SETTEXT` 経由）なら確実に入る。
入力方法を 5 通り比べて、成功したのは win32 のみだった。

欄の特定にも注意が要る。ダイアログにはアドレスバーや検索欄など Edit が
複数あり、**ファイル名欄の control_id は Windows 11 では 1001**
（よく知られた 1148 ではない。UIA 側には 1148 の要素自体が存在しない）。
`logic/runner.py` の `_set_dialog_filename()` は 1001 → 1148 → 先頭の Edit
の順に試し、**入れたあとに読み返して**一致しなければ次の候補に進む。

### 起動時に WaitForInputIdle を使わない

`Application.start()` は既定で `WaitForInputIdle` を呼ぶ。起動用の exe が
コンソールプロセスだと「指定されたプロセスは GUI プロセスでない」
（エラー 1471）で落ちる。`wait_for_idle=False` を渡し、起動できたかは
手順の「終わった合図」で判断する。

さらに、起動用の exe と画面を持つプロセスが別のことがある
（ランチャー型のアプリ）。`_rebind_to_window()` で画面を持つ PID へ
結び直している。これをしないと「アプリを閉じる」でランチャーだけ落として
本体が残る。

### schtasks の出力は UTF-8

日本語環境でも `schtasks` は UTF-8 で出力する。コンソールのコードページ
（cp932）で読むとタスク名が化け、シナリオ名と照合できなくなる
（`win_rpa_クエリ検証_実行` → `win_rpa_繧ｯ繧ｨ繝ｪ讀懆ｨｼ_螳溯｡�`）。
登録は成功しているのに一覧に出てこない、という形で表面化する。

### Tk のウィジェットに `_register` という名前を付けない

`tkinter.Misc._register(func)` を上書きしてしまい、`Toplevel.__init__` の
中（`protocol("WM_DELETE_WINDOW", ...)` の登録）で TypeError になる。
ダイアログが**生成された瞬間に落ちて、何も表示されない**。

同様に避けるべき名前: `_bind` / `_configure` / `_create` / `_displayof` /
`_do` / `_getboolean` / `_getconfigure` / `_getdoubles` / `_getints` /
`_grid_configure` / `_gridconvvalue` / `_loadtk` / `_options` /
`_register` / `_report_exception` / `_root` / `_setup` / `_substitute` /
`_windowingsystem`。

ダイアログはクラスを作った時点で落ちることがあるので、
**生成できることを検証に含めること**（`ui/` の各 Toplevel を
1 回ずつインスタンス化して `winfo_exists()` を見る）。

### デスクトップのパスは決め打ちしない

OneDrive 同期環境ではデスクトップの実体が
`C:\Users\<名前>\OneDrive\デスクトップ` に移る（この開発機がその状態）。
`Path.home() / "Desktop"` は空振りするので、
`WScript.Shell` の `SpecialFolders("Desktop")` から取る。
